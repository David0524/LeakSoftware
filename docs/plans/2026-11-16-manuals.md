## What ships

| Piece | Where |
|---|---|
| Manual chooser | `sundeckpro.com/manual` |
| Pool Care manual (maintenance shops) | `sundeckpro.com/manual/pool-care` + PDF download |
| Leak Detection manual | `sundeckpro.com/manual/leak-detection` + PDF download |
| PDFs | `apps/web/public/manual/sundeck-pro-{pool-care,leak-detection}-manual.pdf` |

One source for both forms: the web page **is** the manual, and the PDF is that page printed by
Chromium with print styles (`scripts/build-manuals.mjs`), so the two never drift apart. Shared
chapters are written once with `<Only edition="pool|leak">` blocks where the shops differ.

Platforms: the manual is a page of the public website, so it works on the desktop and the
mobile website. Linking it from the iPhone and Android apps (More › Help) is an owner decision,
asked at the end, not built here.

## Design

Editorial, not a help-center. Each chapter mixes:

- **Chapter opener**: big number, display title (Barlow), one-line promise, "In this chapter".
- **Walkthrough steps**: numbered, exact button names in bold, the screen beside them.
- **Screens**: iPhone screenshots in a device frame; website screenshots in a browser frame,
  with numbered callouts where a screen has several parts.
- **Tip** (blue), **Good to know** (neutral), **Watch out** (warning brown) asides.
- **Put it to work**: what a feature can be used for, as short scenarios ("Monday, 7:40 a.m.").
- **Why it matters**: the effect on the shop (time, money, trust), shown with plain numbers
  from the product, never sales lines.
- **Pull quotes / big figures** in large display type to change the rhythm.
- **Who can do this** chips (Owner, Admin, Tech) and **Where** chips (Website, iPhone, Android).

Brand from `brand/tokens.json` (navy, water blue, one orange highlight per spread), Barlow Semi
Condensed for display, Public Sans / system for body, tabular numbers for money and PSI.
Print: Letter, cover page, contents with page numbers, chapter starts on a new page, running
footer with edition and page number.

## Told as a story (owner, 2026-11-16: "almost be told as a story … show this as kind of like a process, rather than just a list of features")

Each manual follows one shop through its real process, in the order it happens, using the demo
shop the screenshots show (Phoenix; Dana the owner, Jake on leak detection, Luis, Priya and
Tony on service routes). Every chapter opens on a moment ("Monday, 6:52 a.m. Priya's phone
lights up…"), then teaches what that moment needs, in the order the shop does it. Features
appear where the story needs them, never as a catalogue; the Settings reference at the back is
the one place that lists.

## FAQ (owner, 2026-11-16: "include a FAQs section on the website and in this manual")

One question list (`apps/web/src/lib/faq.ts`), grouped by topic and tagged pool / leak / both,
feeds: a new **/faq** page on the website (package switch, grouped, FAQPage structured data,
linked from the home page's "Good to know" and the footer) and the FAQ chapter of each manual.

## Order of work

1. **Research** (Sonnet helpers, parallel): fact sheets per area from `docs/DECISIONS.md`,
   `docs/design/`, the website code, and the iPhone app: exact labels, rules, roles, package,
   which screenshot shows it. Nothing goes in the manual that isn't in the product.
2. **Framework** (me): `/manual` routes, the manual components (chapter, step, tip, screen
   frames, callouts, figures), print styles, the PDF script.
3. **Screens**: iPhone screenshots from CI's `iphone-screenshots` artifact (161 simulator
   screens, cropped to the phone's viewport, WebP); website screenshots of the demo shop on
   sundeckpro.com, desktop and phone size (Sonnet helper, Playwright). Images are converted and
   sized by a Haiku helper.
4. **Writing**: Opus writes the story chapters of Part II and the prologues;
   Sonnet writes the rest; Haiku drafts the glossary and the settings reference tables from the
   fact sheets. Every chapter is checked against the fact sheets.
5. **Assembly and review** (me): build, read every page at desktop and phone width, print both
   PDFs, page through them, fix what looks wrong.
6. **Ship**: checks, commit, push, CI; merge per CLAUDE.md.
